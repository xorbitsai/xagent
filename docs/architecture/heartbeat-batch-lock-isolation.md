# 心跳批量续租的锁竞争隔离

## 目的

每个后端进程仍使用共享心跳管理器，一次批次使用一个连接、一个事务。PostgreSQL 上某个 Task 被锁时，其余任务先完成续租，被跳过任务提前重试。SQLite 保留原有条件更新路径。

原实现逐条 UPDATE、最后统一提交。等待一条记录会同时拖住先前更新的提交和后续更新；异常回滚整个批次。改动集中在 `task_lease_service.py`，不涉及表结构、迁移、全局 TTL、连接池或其他写入路径的锁协议。

## PostgreSQL 批次

1. 按完整 task、runner、run、attempt 身份选择 RUNNING 的候选，用 `FOR NO KEY UPDATE OF tasks SKIP LOCKED` 取得可用行锁。NO KEY UPDATE 保留与 checkpoint 外键 KEY SHARE 的兼容性。
2. 同一事务内批量 UPDATE 选中行，继续携带完整任期与状态条件。时间在取得候选锁后计算，避免把此前连接等待算入新的 TTL。
3. RETURNING 返回完整任期四元组；不能只按 task_id 判定成功，因为同一批次可能包含同一 Task 的新旧 attempt。
4. 对未更新项，普通查询读取已提交的所有权和状态，区分任期丢失、任务结束和本轮未续租。缺失 run/attempt 永远不是合法任期。
5. 提交成功后才返回成功结果；真正的数据库错误仍回滚整个事务，不能声称局部更新成功。

| 结果 | 含义 | 管理器处理 |
|---|---|---|
| REFRESHED | 续租已提交 | 清除待重试和可恢复错误 |
| SETTLEMENT_READY | 当前可见记录仍属该任期，但已非 RUNNING | 正常停止心跳 |
| LOST | 当前可见记录已不存在或任期不匹配 | 沿用任期丢失处理 |
| DEFERRED | 同任期 RUNNING，本轮未取得更新机会 | 保留注册，稍后重试 |

并发接管或结束尚未提交时，可以先得到 DEFERRED，后续再观察提交结果。DEFERRED 不触发 terminal_event，也不清除此前未解决的 pool_timeout。启动前的 `validate_preacquired_task_lease_isolated` 保留原单任务条件更新，必须取得明确结果，不能把 DEFERRED 当作允许开始执行。

## 调度和停止

每个 entry 保存重试时刻和连续跳过起点。正常心跳周期保持不变，被跳过项在 `min(1 秒, 心跳间隔 / 4)` 后重试；同时最多一个 worker，不新增每任务线程或连接。

- 提前重试只发送到期的被跳过项，正常周期到期处理全部活动项；同时到期合并执行。
- 重试跨过正常周期时，立即补跑正常批次，不能把其他健康任务推到下个周期。
- 真正数据库错误退回正常周期重试，避免错误状态下的高频重试。
- 注销只等待当前 worker 清理，不等待未来重试。结果应用到当次 entry 对象，旧批次的迟到结果不能给替代注册安排重试。
- 重复取消仍通过现有 cancellation-safe 边界等待 worker 完成，不遗弃事务或线程。
- debug 日志记录本批跳过数量及最长连续跳过时间。

## 等待预算和边界

PostgreSQL 心跳事务的局部 statement_timeout 为 `min(5 秒, TTL / 4)`，lock_timeout 为 `min(1 秒, statement_timeout)`。预算不跟随提前重试频率缩短，仅在本事务生效。无竞争本机 2000 项批次耗时约 159ms，低于默认语句预算；这不是所有生产部署都能满足预算的保证。

`SKIP LOCKED` 只跳过行锁，表锁等仍可能等待并触发超时。连接获取沿用连接池超时。这些不是整个数据库调用的严格端到端期限，尤其网络和提交异常仍需原数据库错误路径处理。

持续被锁的任务仍可能过期，提前重试不保证无饥饿。本次隔离对其他任务的影响，不新增本地 TTL 到期强制取消协议。停止心跳后，任务自己的收尾仍可能等待其他事务持有的锁。

PostgreSQL 语义参考：[锁定查询](https://www.postgresql.org/docs/current/sql-select.html#SQL-FOR-UPDATE-SHARE)、[行锁兼容性](https://www.postgresql.org/docs/current/explicit-locking.html#LOCKING-ROWS)。

## 回归与性能验证

`test_task_lease_heartbeat_batch.py` 覆盖真实 PostgreSQL 的锁跳过、外键兼容、提交失败回滚、任期变化及缺失令牌、表锁超时、启动前明确校验，以及真实数据库与共享管理器的提前重试联动。受控单调时钟测试覆盖正常周期、仅热点重试、错误保留、慢重试跨周期、注销替代注册和重复取消。

SQLite 继续执行既有租约回归，新增 PostgreSQL 专用实例在 SQLite 下跳过。PostgreSQL 测试已加入 `test-migrations.yml` 的触发路径、变更筛选和实际执行步骤，避免仅在本地运行。

相关租约、心跳、编排、数据库取消边界及收尾测试：242 项通过，20 项数据库不适用实例跳过。

本机 PostgreSQL 16，无竞争批次，每组预热一次，三次测量取中位数；对照为 `f7e8af060` 的真实批次函数，更新相同模型：

| 租约数 | 修改前 | 修改后 | SQL 语句数（前 → 后） |
|---|---|---|---|
| 10 | 2.24ms | 1.29ms | 10 → 3 |
| 100 | 18.62ms | 5.74ms | 100 → 3 |
| 500 | 110.48ms | 29.59ms | 500 → 3 |
| 2000 | 696.75ms | 159.03ms | 2000 → 3 |

语句数包含新实现的事务局部超时设置，不包含协议级提交。存在未更新项时增加一次分类查询。该合成结果证明样本中批量 SQL 减少了往返开销，不代表生产吞吐或持续热点的公平性保证。
